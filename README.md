# AI Генератор

Небольшая страница для запросов к модели OpenAI gpt-oss-20b через OpenRouter. Браузер обращается к локальному Node.js-серверу, а секретный API-ключ хранится только в `.env` на сервере.

## Что нужно установить

- Node.js версии 18 или новее
- API-ключ OpenRouter: https://openrouter.ai/keys

## Запуск

1. Откройте папку проекта в терминале.
2. Скопируйте `.env.example` в файл `.env`.
   - Windows PowerShell: `Copy-Item .env.example .env`
   - macOS/Linux: `cp .env.example .env`
3. Откройте `.env` и замените `вставьте_свой_ключ_сюда` на свой ключ OpenRouter.
4. Запустите сервер: `npm start`.
5. Откройте в браузере http://localhost:3000.
6. Введите запрос и нажмите «Отправить запрос».

Для автоматического перезапуска сервера при изменениях используйте `npm run dev`.

## Проверка

- Откройте главную страницу и отправьте короткий запрос, например «Привет! Представься в одном предложении».
- Без `.env` или ключа страница покажет подсказку о настройке.
- Чтобы проверить сервер без вызова модели, отправьте пустой запрос:
  `curl -X POST http://localhost:3000/api/chat -H "Content-Type: application/json" -d "{}"`
  Ожидается ошибка с подсказкой, что запрос пустой (если ключ настроен).

## Переменные окружения

- `OPENROUTER_API_KEY` — обязательный секретный ключ. Храните его только в `.env` локально или в переменных окружения хостинга.
- `OPENROUTER_MODEL` — необязательное имя модели; по умолчанию `openai/gpt-oss-20b`.
- `PORT` — необязательный порт; по умолчанию `3000`.

Статический хостинг (например, GitHub Pages) не запускает этот сервер. Для публикации выберите Node.js-хостинг, который поддерживает переменные окружения, и задайте там `OPENROUTER_API_KEY`. Не публикуйте `.env` и не помещайте ключ в `index.js`, HTML или другие клиентские файлы.

## Загрузка на GitHub и публикация через Vercel

### 1. Подготовьте репозиторий на компьютере

1. Установите GitHub Desktop и войдите в аккаунт GitHub.
2. Выберите **File → Clone repository** и клонируйте свой репозиторий.
3. В Проводнике откройте клонированную папку. Скопируйте туда файлы из этой подготовленной папки проекта, согласившись заменить файлы с такими же именами. Не копируйте `.env` и не удаляйте скрытую папку `.git` из клонированного репозитория. Скопировать `.env.example` можно: в нём нет секрета.
4. В GitHub Desktop проверьте список изменений. Введите сообщение, например `Add AI prompt and Vercel API`, нажмите **Commit to main**, затем **Push origin**.

Если в репозитории уже был старый workflow для GitHub Pages, удалите его: статическая публикация Pages не запускает API-функцию. В подготовленной копии небезопасный workflow, который вставлял ключ в браузерный код, уже удалён.

### 2. Подключите репозиторий к Vercel

1. Войдите в Vercel и нажмите **Add New → Project**.
2. Подключите GitHub, если Vercel попросит, затем выберите нужный репозиторий и нажмите **Import**.
3. Оставьте корневую папку проекта (`./`). Для этой простой страницы сборочная команда не нужна; Vercel обнаружит статические файлы и функцию в `api/`.
4. Перед публикацией добавьте переменную окружения `OPENROUTER_API_KEY` со своим новым ключом. Выберите как минимум окружение **Production**; **Preview** можно добавить тоже. Не добавляйте ключ в код, GitHub или `.env.example`.
5. Нажмите **Deploy**. После успешной публикации откройте выданный адрес Vercel и отправьте запрос.

После этого каждый `Push` в подключённую ветку автоматически запускает новую публикацию. Если добавили или изменили переменную окружения уже после первой публикации, запустите повторный **Redeploy**: новые переменные применяются к новым деплоям.

GitHub хранит исходный код, а Vercel запускает сайт и API. Переменную `OPENROUTER_API_KEY` добавляйте только в настройках проекта Vercel. Старые опубликованные API-ключи следует отозвать в OpenRouter.
